# Structure review: prd.md

**Read:** This document exists to help a five-person hackathon team, and the UX, architecture, and epics writers who follow it, build the AgentDesk MVP in three days by fixing what it does in testable terms and in what order to build and cut it.

**Model:** Strategic/Context (Pyramid) for the frame (§0 to §2, §5 to §11); §4 Features judged as Reference/Database (identical FR schema, random access). The document fits this hybrid well: the headline (§1) and concrete journeys (§2.3) come first, every FR follows one shape, and the build-order table (§6.3) is the cut guide. The findings below are refinements, not a reshaping.

**Reader:** humans (default). Downstream BMad skills also consume the document, so a single source of truth for each rule matters more than usual.

**Word metrics:** 8,109 words total, from `word_metrics.py`. Per-section counts are cited in each row.

## Summary

- Recommendations: 7 actionable (1 CONDENSE, 1 MERGE, 3 MOVE, 2 QUESTION) and 3 PRESERVE.
- Estimated reduction if every recommendation is accepted, including the FR-37 merge: ~135 words, about 1.7% of 8,109. Without the FR-37 merge: ~120 words, about 1.5%.
- No length target was provided. The document is already dense; the value of these changes is a single source of truth for rules and a better reading order, not length.
- Comprehension trade-offs: the glossary condense adds one hop for rule lookups; the §6.1 move removes the closing recap; the FR-37 merge changes the FR count the team chose.
